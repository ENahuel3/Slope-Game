# Slope (modded)

**Play it here: https://enahuel3.github.io/Slope-Game/**

A modded fork of [cgolden15/Slope-Game](https://github.com/cgolden15/Slope-Game), which is a self-hostable copy of the Slope game by Y8 Games / IDnet. This fork lives on the `mod` branch and is what GitHub Pages serves.

## What the mod changes

- **No ads, no tracking.** The page shell is a plain HTML5 document with the ad slots, analytics and promo banner removed, and `TemplateData/mod.js` blocks the game's own calls to the id.net / y8 / Unity Analytics backends before they leave the browser. The in-game app-store button and the Y8 "more games" branding are disabled inside the scene data (`Build/slope_data.unityweb`). A stray token at the end of `unityloader41.js` that threw a `ReferenceError` on every load is fixed.
- **HUD.** Fullscreen (button or **F**, the whole page so the HUD stays usable), a session timer, a **Courses** box, a **Rainbow** toggle and a **Music** selector. The HUD hides while you play and comes back when the mouse moves. Settings persist in the browser.
- **Stacked courses, instantly.** Type a number into **Courses** and every run starts with that many random courses sitting exactly on top of each other: the rapid-Enter restart glitch turned into a feature, built in a fraction of a second while the ball is still dropping into the start tunnel. Changing the number applies at the next restart. The stack applies on a straight track only: hidden courses are built in one frame and cannot follow a rolled lane, so with *Curves* or *Twists* on, the number is dimmed and one course is played (the straight hidden lanes used to cut through the rolled lane and wedge the ball).
- **Instant restarts.** Press **R** at any time to restart with a fresh stack. When the ball dies the mod shows the death for half a second and restarts with the stack rebuilt; there is no game-over screen and no Enter to press. With Courses set to 1 a death goes through the normal game-over screen.
- **Music.** Original, *Aria Math (Phonk Remix)* or *Mort Jackson – Billie Jean*. A custom track keeps its place across restarts (it pauses when the game would stop its own track and resumes when a run starts), and switching mid-run is immediate.
- **Track shaping.** The course rolls about its own centre line, as real, continuous geometry. *90° twists* roll a quarter turn over twenty blocks; *Curves* roll 120 to 240 degrees, one block at a time, so you ride up onto what was the wall, over the ceiling and back. Two copies of the lane-block prefab are added to the scene bundle whose surface and neon walls are helicoids twisting by exactly +4.5° / -4.5° from start to end (`tools/patch_roll.py`, meshes generated from the block's shape, collision cooked at runtime), so a run of them is one smooth ribbon and the next block starts where the last ended. The spawner's lane-block spawns take their prefab from a new FSM GameObject variable (`ModBlock`); the mod decides for each upcoming block whether it is flat or a helicoid in either direction and writes that prefab's object pointer, together with the block's start rotation (`ModQ1` and the spawn transform), before the block is spawned. Every spawner step is gated so exactly one step runs per mod frame while a track mode is on, whatever Unity's update rate: the step takes its `Wait` time from `ModHold` (0 = the vanilla one-frame burst, which stacking relies on; 1000 s = hold) and the mod releases one step per frame by zeroing it; a `ModMark` flag tells the mod which steps spawned a helicoid-capable block so the roll only advances across those (tilted, thin and dogleg pieces stay rigid at the roll they were spawned at). The ball's frame follows the built course exactly: each block record carries its start and end roll, gravity, the forward push and steering are rotated into that frame through the WebAssembly heap, and the camera rig follows it, so the view rolls with the lane. `tools/patch_spawner.py` / `tools/patch_rotations.py` make every block copy the spawner's rotation, `tools/patch_sections.py` splits the spawner's section states into one step per block, `tools/patch_triggers.py` repairs the checkpoint triggers for the rolled spawn frame, and `tools/fsmparse.py` / `tools/fsmwrite.py` are the PlayMaker FSM parser and serializer behind all of it. The HUD **Track** selector offers Straight, Curves, 90° twists, or both.
- **Rainbow neon.** Every fragment shader is rewritten at compile time so the green neon becomes a diagonal rainbow that scrolls across the screen and ripples with a travelling wave. Red stays red.
- **Community editor.** Type `awesome` on the page and a box appears where you can ask Claude Code to change the mod. The request runs on a sandboxed clone on the owner's server within a spend budget, the result is validated and pushed here, and GitHub Pages serves it to everyone a minute later. Details, containment and setup: [`edit-server/README.md`](edit-server/README.md). When the service is offline the box says so.

## How the stack works

The game logic is a set of PlayMaker state machines inside the Unity WebGL build, and Unity's `SendMessage` bridge lets the page switch their states by name (`SetState`). The mod spawns each hidden course directly: the Sphere's `Restart Game` state puts the ball and the spawn point back at the origin, the spawner's `spawn go tunnel run` state drops a start section there and `Check score` generates one lap per call (the spawner's own per-speed-up path, so laps go easy, medium, hard like a real run). The last course goes through the game's own `resetGame` restart so the game state is clean. Nothing on that path removes old blocks.

Clearing and restarting instantly is the tricky part. A death queues a `death complete` broadcast three seconds later, which is what despawns the course and freezes time at the game-over screen; a restart issued before it lands defuses it, so the mod restarts half a second after a death, then despawns everything through the spawner's `DestroyBlocksPool` state (forcing `start game` in the same frame, because that state also stops time and the despawn only executes once time runs), rebuilds the stack and restarts again. The draw list and the WebAudio music track are the only signals the mod reads back from the game.

## Hosting your own copy

Fork this repository, open **Settings → Pages**, set the source to the `mod` branch (root), and the game will be served at `https://<your-user>.github.io/Slope-Game/` after a minute or two. If a network blocks the URL, renaming the repository changes it. There is no build step; it is static files.

## Load time

`Build/slope_data.unityweb` (the scene data, 8.6 MB raw) is stored gzip-compressed with the comment marker Unity's loader looks for (`UnityWeb Compressed Content (gzip)`; `unityloader41.js` only inflates a gzip stream that carries it and passes any other file through untouched, so a plain `gzip` would break the load). GitHub Pages does not compress `.unityweb` files itself, so this cuts the first-visit download from about 14 MB to 8 MB; `tools/unitygz.py` compresses or decompresses a bundle, `tools/pack_webdata.py` writes the compressed form by default (`--raw` for the old one) and `tools/unpack_webdata.py` reads either. `Build/slope.json` also turns on the loader's IndexedDB cache (`cacheControl: must-revalidate`): a repeat visit sends conditional requests for the three engine files, gets `304 Not Modified` back and reads them from the cache, about 0.3 MB of transfer instead of 8 MB, independent of the browser's HTTP cache evicting them. `tools/stackfreeze.py` (needs `playwright`) is the soak test for the stacked-course and game-over freezes: it plays a stack of N courses with the mod's lane-centering autopilot and reports lap spawn bursts, frame gaps, a stalled ball and every console error, and `--audit` lists the heap candidates per variable by class. `tools/bench_load.py` (needs `playwright`) serves the repository locally, loads the page in headless Chromium at a chosen bandwidth, reports the bytes and the time to the menu, then starts a run on a curved track to prove the game plays; `--runs 2 --profile DIR` shows the second visit served from the cache.

## Versions

The page at the site root is always the latest version. Older releases are complete copies under `versions/<tag>/`, listed in `versions/index.json`, and the HUD's **Version** selector (`TemplateData/versions.js`) switches between them; an old version shows a note with a link back to the latest. A snapshot shares the engine files, the loader and the music tracks with the root when they are byte-identical (those files have not changed since the fork and must not be removed or modified in place; a changed file is copied into the snapshot instead), so each one costs about 9 MB on the site and nothing in the repository when its files are already in the history. Because every snapshot is self-contained, a broken latest version never takes the older ones down: players just pick one that works.

To freeze the version you are about to replace, before publishing a risky change:

```
python3 tools/snapshot_version.py v7-slabs --from HEAD --title "Three-slab geometry" --notes "..."
python3 tools/snapshot_version.py --latest --title "What the root version is now"
```

Every version that has been live is kept, including broken ones (the picker is how a player escapes a bad latest version): `v4-stack`, `v5-gravity`, `v6-track`, `v7-slabs`, `v8-gapwrap`, `v9-forward`, `v10-fastload`, `v11-nofreeze`, and so on. The rule is enforced by `.githooks/pre-push` (install once per clone with `git config core.hooksPath .githooks`): a push to `mod` is refused while the version it replaces, the remote's current head, is not in `versions/index.json` (by commit hash, or by having the same `index.html`, `TemplateData` and `Build` trees as a listed version, or by the push changing no game file at all, so a commit that only touched the versions, the tools or this file needs no snapshot of its own).
